# Meeting Accuracy Follow-up

This local development build improves speech-window planning, preserves speaker
attribution across supported short pauses, and reviews weak speaker regions with
the existing ERes2Net model. No new CLI option, model download, or cloud service
is required. ASR windows are frozen before acoustic speaker review; the review
cannot rewrite recognized words. JSON changes retain `original_speaker` and
`attribution_method`. Their silhouette is unavailable (`confidence: -2`), not a
new calibrated probability.

## Private Meeting Comparison

The user authorized a 35:17 mono meeting recording and supplied a reference
transcript plus 24 terms. The transcript is not verified human ground truth.
It is evaluation input only, never an inference prompt or speaker identity
source. This meeting is development data, not an independent acceptance set.

All prompted comparisons use exactly the same terms, Turbo q8, automatic
language selection, ERes2Net, and CoreML + Metal, with inference network denied.
Normalization is unchanged: ICU Hant-Hans, NFKC, case folding, and alphanumeric
characters. No number, filler, or terminology substitutions are applied.

Relative to prompted rc.2, total text edits fall from 1803 to 1722 over 8391
reference characters. Substitutions fall from 582 to 560 and insertions from
769 to 695, while deletions rise from 452 to 467. This is not a uniform
improvement in every error type or proof of absolute recognition accuracy.

Speaker review changes eight regions totaling 12.046 seconds. Its input/output
ASR text is byte-identical. With that text fixed, 6012 matched reference
characters have 107 to 60 different-speaker assignments, 5446 to 5490 agreeing
assignments, and 459 to 462 unknown assignments. Raw speech and overlap coverage
are unchanged. cpCER also falls with unknown text retained as missing reference
content; the improvement does not rely on silently crediting unknown words.

The three remaining long conflicts are not the total number of errors. Short
words near corrected boundaries still have wrong or unknown labels. There is
no verified speaker timeline, so private DER is not reported. The runtime
observations are from a shared host and are not a controlled overhead benchmark.
Private audio, reference text, speaker identities, and detailed reports remain
outside Git.

## Automatic Selection And Default Transcript

A subsequent change keeps the same command and optional terminology prompt.
File transcription now finishes its initial transcript before reviewing extra
windows containing three consecutive low token scores. Candidates must pass
the existing semantic guards; a local replacement may also be selected when
the changed region gains sufficient score without reducing the whole-window
score. Raw token scores are kept separately from acoustic timestamp grouping.
JSON records `local_token_selection` and `decoding_stats`; token scores still
are not calibrated correctness probabilities.

Default text combines adjacent same-speaker fragments into paragraphs, retaining
words, time positions, unknown labels, and overlap. Internal review flags stay
in JSON and no longer create manual correction tasks in the transcript or the
completion message. Paragraph formatting itself does not improve recognition.

The final file-selection build was checked with fixed public development audio,
automatic language selection, no prompt, network denied, and Metal using the
same model weights in each pair. The four short meeting baselines reuse the
verified earlier run; Mandarin/mixed-language baselines use the previous local
build. The short speaker-refinement stage makes no changes on these fixtures.

## Offline Volume Normalization and Speech Coverage

File transcription now uses FFmpeg dynamic normalization with explicit defaults
(`f=500:g=31:p=0.95:m=10`). Original and normalized audio must contain the same
number of samples. VAD runs on both and the planner merges their speech ranges;
contained/overlapping intervals cannot create false pause boundaries. ASR uses
normalized audio, while diarization and speaker refinement use original audio.
The live sample path is unchanged. There are no new CLI options or model files.
JSON records `decoding_settings.volume_normalization`.

The final binary SHA-256 is
`1939825b508f3370b9bd1a3cee5d842c0ccf2bcd5a02657974d17c17c5686b74`.

Both use the same Turbo q8 weights, Metal, automatic language, no prompt, and
denied network access. Public annotations and scoring normalization are unchanged.
