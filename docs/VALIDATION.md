# 本地会议验证记录

## 环境与样本

- 本机：Apple M2 Pro，16GB 内存，macOS。
- ASR：whisper.cpp v1.8.3，large-v3-turbo q8，CoreML + Metal。
- 当前默认说话人：sherpa-onnx v1.13.8，Pyannote segmentation-3-0，3D-Speaker ERes2Net Base（zh-cn，16kHz），CPU。
- 历史集成测试使用 2026 年 9 月 24 日的真实录音：26.50 秒、208.96 秒、6396.29 秒。
- 从完整会议另取 600–720 秒的中英文术语片段，以及两段纠错问题片段。
- 用户确认完整会议有 4–6 位主要发言者；没有逐字参考稿或逐句说话人标注。
- 另使用用户提供的 4976.9 秒现场会议及配套纪要验证观点归属；该会议的参会名单有 15 人，不能套用上场的 4–6 位人数。
- 录音与转写结果保存在用户本机，未加入 Git。

## 自动检查

以下检查已通过：

- Release 编译、CTest、安装文件名和安装脚本内容检查。
- `git diff --check`、Shell 语法检查、SKILL 元数据验证。
- 会议分段、文本拼接与输出测试的 AddressSanitizer / UndefinedBehaviorSanitizer 检查。
- 分段覆盖、停顿边界、UTF-8 字符与英文词拼接、正常重复词保留。
- 退化时间戳保留尾部文字，输出时间单调、正时长且不越过录音结尾。
- 声学时间对齐合并同帧 UTF-8/BPE tokens；无效声学时间回退，禁止按插值拆分说话人观点。
- 说话人覆盖不足、短弱聚类、负聚类置信度和重叠发言保留不确定状态。
- 纠错保护数字和否定词；拒绝大量删文、大幅改写和重复程度增加。
- JSON 解析、全文等于片段文本拼接、分数范围与字段类型检查。
- `text/json/srt/vtt` 输出与输出写入失败处理。

系统禁止网络连接后完成真实录音转写，使用：

```bash
sandbox-exec -p '(version 1)(allow default)(deny network*)' \
  /path/to/asr-tool /path/to/meeting.mp4 \
  -p "TKPH、MAP、rolling hours、cycle、graph、空车、载重" \
  -f json -o /path/to/meeting.json
```

禁网环境下还验证了空文件、静音、缺失/损坏 ASR 或 VAD 模型、缺失说话人模型、
同等大小但损坏的分段/声纹模型、无效参数、`--no-speakers` 和缓存模型准备。
缺失/损坏说话人模型会告警并继续输出文本；ASR/VAD 失败不会冒充成功转写。

## 历史完整会议结果（WeSpeaker）

此前使用 WeSpeaker 的实现运行完整 6396.29 秒录音，成功输出：

- 3320 个文本片段，语言为 `mixed`，6 处自动纠错，保留纠错前后文本。
- 7 个说话人标签和不确定标签；其中 3 个标签对应的文本时长不足 3 秒。
  与用户确认的 4–6 位主要发言者存在偏差，不能宣称人数或逐句归属准确。
- 698 个片段标为重叠发言，3302 个片段标为需复核。近似时间戳按窗口标记，
  因此复核比例很高，不能据此推算文字错误率。
- 输出末尾时间为 6396.155 秒；全文与片段文本拼接一致，全部时间戳通过检查。
- 两处已发现的增加重复和大量删文候选，在收紧规则后的整场结果中均未采用。
- 该历史运行耗时 975.59 秒，最大常驻内存 1.42GiB。这些数据不代表当前
  ERes2Net 加声学对齐实现的性能，也不能用于证明速度提升。

## 当前现场会议结果（ERes2Net + 声学对齐）

4976.90 秒的单麦克风现场会议已在禁网环境下完整执行，另用用户提供的会议纪要
做观点语义对照。纪要不是逐字稿，也不是带时间戳的说话人参考标注。

- 输出 1924 个文本片段、1336 个独立说话人时间段、6 处本地重解码纠错。
- 全文与片段文本拼接一致；文本与声音时间段均通过正时长、范围、字段类型及
  分数检查。最后一个文本片段结束于 4902.570 秒；这不证明后面的音频没有遗漏。
- 1516 个片段标为需复核。原因计数可重叠：文字低分 1070、纠错候选被拒 784、
  说话人不确定 898、重叠发言 83、近似时间 27、重复 4。
- 文本中出现 12 个匿名说话人标签；只有 5 个标签对应文本的累计时间超过
  100 秒，其余多数很短。不能把这些标签解释为真实参会人数。
- 已输出文本片段的累计时间为 3742.19 秒；其中未知说话人 1579.07 秒、重叠
  111.08 秒，合计 45.17% 没有单一说话人归属。分母是文本片段时间，不是整场
  录音时长；该比例不是 DER，也不是正确率。
- 运行耗时 885.03 秒，最大常驻内存约 1.49GiB。该次运行二进制 SHA-256 为
  `292a26f3dffaefcd94bd92ba24b949e91a878c3b0ffe5e1961e6b429e1b549c5`，
  使用 DTW 对齐、greedy 首次解码及 beam 重试。其后对齐预设的文件名判断和
  helper 整理改变了二进制；该时耗不是最终安装二进制的独立性能测试。

观点对照未通过“可靠归属”的验收：纪要中同一人的若干主题落在不同标签，
多个署名人的主题也出现在同一标签下，存在疑似拆分、合并或多人延续同一议题的
情况。实体关系等重要观点有文字匹配，但多数归属未知。仅凭主题不能判断发言人
身份，尚不能断言这些疑点均为声纹错误，也不能宣称观点没有混淆。

文字仍有较多同音误识别和疑似异常外语输出。一段 45 秒诊断片段在另一组上下文、
窗口边界和术语提示下未复现整场中的外语输出；该片段 `auto` 与 `zh` 的正文一致，
但仍有明显不通顺内容。这不能证明强制中文有效，也没有逐字稿支持准确率比较。
没有据此新增中文锁定、外语过滤或自动改写规则，避免破坏真正的中英文混合录音。

带姓名、原文摘录、时间点和待核对事项的详细报告仅保存在用户本机，未加入 Git。

## 质量边界

- 功能通过不等于识别正确率提高。术语片段仍出现“空车载重”和 `cycle` 的误识别；
  没有人工参考稿，不报告 CER/WER 或纠错准确率。
- 说话人自动聚类仍可能拆分或合并。标签数量不能当作实际人数，短促插话、
  远场和同声发言仍需听音核对；工具没有声源分离能力。
- 当前默认先进行声学时间对齐，失败后才采用近似时间。退化时整句保留，只有全句
  说话人证据一致才分配标签。近似时间会标记 `needs_review`，标记数量不是文字错误数量；
  留空降低了错误归属风险，但增加漏判，不能用低混淆量掩盖高弃判比例。
- 自动纠错采用重新解码的候选，置信度仍只是 token 分数。保守筛选可能拒绝正确的
  大幅修改，但保留原文和复核状态，避免默默重写会议内容。
- 完整录音 PCM 和临时 WAV 随录音长度增长；本轮未验证超长录音的资源上限。
- Linux、Windows 和 NVIDIA 仅保留构建/打包路径，本机没有进行这些平台的运行测试。
